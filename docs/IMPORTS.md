# Reuse JSON graphs with named imports

Add an `imports` object mapping short names to JSON files. Reference a node inside
an imported recipe as `alias.node`:

```json
{
  "size": 2048,
  "tile": true,
  "imports": {
    "glass": "glass.json",
    "dust": "dust.json",
    "prints": "fingerprints-scattered.json"
  },
  "nodes": {
    "dusty": {
      "op": "blend",
      "a": "glass.roughness",
      "b": "dust.dust",
      "mode": "add",
      "opacity": 0.35
    },
    "handled": {
      "op": "blend",
      "a": "dusty",
      "b": "prints.scattered-prints",
      "mode": "add",
      "opacity": 0.22
    },
    "roughness": {
      "op": "math",
      "input": "handled",
      "mode": "clamp",
      "range": [0, 1]
    }
  },
  "outputs": {
    "roughness.png": {"node":"roughness", "bits":16},
    "color.png": "glass.color",
    "normal.png": {"node":"glass.normal", "bits":16}
  }
}
```

Save beside the three referenced samples. No separate rendering or intermediate
PNG files are needed: the imported nodes join the same execution graph.

## Complete glass example

[samples/handled-glass.json](../samples/handled-glass.json) combines the glass, dust
and scattered-fingerprint samples and exports a connected MaterialX material:

```sh
./build/texutil samples/handled-glass.json --out out/handled-glass
./build/texutil validate samples/handled-glass.json --json
```

The graph adds dust and fingerprints to roughness, keeps the imported glass color,
normals, height and transmission, and exports both reusable masks. Its native sheet
shows clean and handled glass illustrations, an amplified wear mask and the actual
roughness. The illustrated haze is a presentation effect; the material's roughness
map supplies the effect in a renderer. It is not a refraction render.

`handled-glass.mtlx` references only this parent graph's exported PNG files. Copy it
with those textures for use in a compatible MaterialX host. Imported material
declarations are not inherited automatically.

## Scope and file rules

- Paths resolve relative to the JSON file declaring them. Nested imports and image
  nodes retain their own declaring directory. For root JSON read from stdin, the
  starting directory is the current working directory.
- Aliases are ASCII identifiers of at most 128 characters: letters, digits and
  underscores, starting with a letter or underscore. Use forward slashes in relative
  file paths for portable sample folders. Absolute import paths are also accepted.
- A nested import is referenced as `outer.inner.node`. Within an imported graph,
  its own references stay local. It cannot reach back into its parent graph.
- Imported nodes retain their existing names inside the alias. Local nodes cannot
  reuse an alias or a name beginning with `alias.`. Conflicts are errors.
- Import the same JSON under two aliases for separate instances. Each has a distinct
  namespace, including private nodes generated by presets. Repeated references to
  one qualified node share one evaluation; separate aliases are separate evaluations.
- Every imported node is validated, including unused nodes. Only nodes required by
  the parent's outputs run. Imported `outputs` declarations are ignored, including
  image, sheet and MaterialX exports; their export references are not validated.

## Settings

| Setting | Behavior |
| --- | --- |
| Image dimensions | The parent's size, including CLI `--size`, applies to all nodes. Imported sizes do not allocate separate canvases. |
| Seed | Imported nodes use their document's seed, or 42 if absent. Explicit per-node seeds take precedence. |
| Tiling | Imported noise uses its document's `tile`, or false if absent. Explicit per-node tiling takes precedence. |
| CLI `--seed` | Changes root nodes' document seed. Imported seeds remain independent. |
| Outputs / format / color space / background | Controlled by the parent document; imported output settings do not carry over. |
| Threads / memory | One shared worker pool and buffer budget for the expanded graph. |

At equal render dimensions, an imported node produces the same values as its
standalone recipe, including preset nodes. Pixel-size effects still change character
when rendered at a different resolution. Root `tile:true` does not make all imported
content seamless; wrapping and source patterns still determine that.

The import syntax currently accepts filenames only. Modify the imported graph or
add parent nodes to adjust its result; per-instance parameter overrides are not
implemented. A library file can omit `outputs`, and an import-only parent can omit
`nodes`. The parent still needs a nonempty `outputs` object and at least one node
across the expanded graph.

## Validation and limits

Import file cycles are rejected using canonical file paths, including cycles through
symlinks. Node cycles, missing references, namespace conflicts and nonexistent image
files also fail validation. Outputs cannot overwrite imported JSON files or image
assets. Limits are 16 nested import levels, 128 import instances, 8 MiB per imported
JSON file, 32 MiB total unique imported JSON bytes, and 4096 total nodes after import
and preset expansion. Files imported more than once are parsed once per graph load.

Keep imported recipes and their relative assets together when copying the source
graphs. A rendered MaterialX/PNG bundle does not require those source JSON files.
